# RouteAlert

**RouteAlert** เป็นแอปพลิเคชัน Flutter สำหรับแจ้งเตือนรถพยาบาลฉุกเฉินที่กำลังเข้าใกล้ (Ambulance Proximity Alert) และเป็นช่องทางแจ้งเหตุอุบัติเหตุ/เหตุฉุกเฉินไปยังศูนย์สั่งการและโรงพยาบาลโดยตรง แบบเรียลไทม์

โปรเจกต์นี้เชื่อมต่อระบบจริงครบแล้ว ไม่ใช่แค่ UI mockup:

- **Cloud Firestore** — เก็บ/ซิงก์ข้อมูลเคสฉุกเฉินแบบเรียลไทม์ข้ามอุปกรณ์ทั้ง 3 role
- **MQTT** (`broker.emqx.io`) — กระจายพิกัด/ทิศทาง/ความเร็วของรถพยาบาลแบบสด
- **Google Gemini Vision API** — วิเคราะห์ภาพหน้างานประกอบการประเมินความรุนแรงเบื้องต้น (AI Triage)
- **Face Login** (biometric, ไม่ใช้ Firebase Auth จริง — ดูหัวข้อความปลอดภัยด้านล่าง)

---

## 🌟 คุณสมบัติหลัก (Features)

- **ระบบแจ้งเตือนรถพยาบาลใกล้เคียง (Ambulance Proximity Alert)** — แจ้งเตือนผู้ใช้ทางถนนแบบเรียลไทม์เมื่อมีรถพยาบาลเปิดสัญญาณไซเรนกำลังเข้าใกล้ พร้อมระยะห่างและทิศทาง แบ่งเป็นวงเรดาร์ (เห็นล่วงหน้า) และวงวิกฤต (ต้องหลบทาง)
- **ระบบแจ้งเหตุฉุกเฉิน (SOS)** — ถ่ายรูปสถานที่เกิดเหตุ ระบุพิกัด GPS และรายละเอียด ส่งตรงถึงศูนย์สั่งการ พร้อมตัวเลือกให้ AI (Gemini Vision) ช่วยประเมินความรุนแรงเบื้องต้นจากภาพ
- **แผนที่แบบเรียลไทม์** — แสดงตำแหน่งรถพยาบาล จุดเกิดเหตุ และสภาพการจราจรบนแผนที่ OpenStreetMap
- **วงจรชีวิตเคสแบบเต็มรูปแบบ** — pending → มอบหมายรถพยาบาล → ถึงจุดเกิดเหตุ → นำส่งโรงพยาบาล → ใกล้ถึง ER → เสร็จสิ้น (แต่ละสถานะซิงก์ทุกอุปกรณ์ผ่าน Firestore)
- **Dark Mode, เสียงพูดแจ้งเตือน (TTS), หน้าแนะนำการใช้งาน (Onboarding) และ Coach Mark** ต่อ role

## 👥 สิทธิ์การใช้งาน 3 กลุ่มผู้ใช้ (User Roles)

1. **ผู้ใช้ทั่วไป / ผู้ขับขี่ (Driver)** — รับแจ้งเตือนรถพยาบาลใกล้เคียง ดูตำแหน่งเหตุการณ์บนแผนที่ กดปุ่ม SOS แจ้งเหตุพร้อมพิกัด
2. **เจ้าหน้าที่รถพยาบาล (Ambulance)** — เปิด/ปิดสถานะปฏิบัติงาน กระจายพิกัดผ่าน MQTT รับเคสจากศูนย์สั่งการ (รับได้ทีละ 1 เคสเท่านั้น) อัปเดตสถานะภารกิจ นำทางไปจุดเกิดเหตุ/โรงพยาบาล
3. **หน่วยงาน / ศูนย์สั่งการ / โรงพยาบาล (Agency)** — แดชบอร์ดเห็นรถพยาบาลทุกคันแบบสด มอบหมายเคสให้คันที่ใกล้ที่สุดโดยอัตโนมัติ (กันรถคันเดียวรับ 2 เคสซ้อน) เตรียมทีม ER ล่วงหน้า ดูจุดเสี่ยงอุบัติเหตุสะสม (Heatmap)

## 🚀 การเริ่มต้นใช้งาน (Getting Started)

### สิ่งที่ต้องมี

- Flutter SDK (`>=3.4.0 <4.0.0`)
- โปรเจกต์ Firebase ของตัวเอง (Firestore เปิดใช้งานแล้ว) — หรือจะใช้ค่า fallback ที่ผูกไว้ใน `lib/firebase_options.dart` เพื่อทดสอบเบื้องต้นก่อนก็ได้
- (ไม่บังคับ) Gemini API key ถ้าต้องการให้ AI ช่วยประเมินภาพหน้างานตอนแจ้งเหตุ — ถ้าไม่ตั้งค่า แอปจะ fallback ไปใช้การประเมินแบบ local engine แทน

### ขั้นตอน

1. Clone repository นี้ลงเครื่อง:
   ```bash
   git clone <URL ของ repository นี้>
   cd route-alert-app
   ```
2. ติดตั้ง dependencies:
   ```bash
   flutter pub get
   ```
3. ตั้งค่าตัวแปรแวดล้อม: คัดลอก `.env.example` เป็น `.env` แล้วกรอกค่าจริง (Firebase config ของโปรเจกต์คุณเอง, Gemini API key ถ้าต้องการ) — ไฟล์ `.env` ถูก gitignore ไว้แล้ว ไม่ต้องกังวลเรื่องหลุดขึ้น Git:
   ```bash
   cp .env.example .env
   ```
4. รันแอป (ต่ออุปกรณ์จริงหรือเปิด simulator/emulator ไว้ก่อน):
   ```bash
   flutter run
   ```
5. รันเทส (ถ้าต้องการตรวจสอบว่าโค้ดยังทำงานถูกต้อง):
   ```bash
   flutter test
   ```

### หมายเหตุเรื่อง MQTT

ค่าเริ่มต้นชี้ไปที่ broker สาธารณะ `broker.emqx.io` (ไม่ต้องสมัคร/ตั้งค่าเพิ่มเพื่อเริ่มทดสอบ) — เหมาะสำหรับ dev/demo เท่านั้น ถ้าจะใช้งานจริงควรเปลี่ยนไปใช้ broker ของตัวเองที่มีการยืนยันตัวตน เพราะ broker สาธารณะใครก็ publish ข้อมูลปลอมเข้ามาที่ topic เดียวกันได้

## ⚠️ ข้อจำกัดที่รู้อยู่แล้ว (Known Limitations)

โปรเจกต์นี้เป็นงานวิทยานิพนธ์ระดับมหาวิทยาลัย มีข้อจำกัดที่ทราบอยู่แล้วดังนี้ (ไม่ใช่บั๊กที่ไม่รู้ตัว):

- ระบบ Face Login เทียบใบหน้าฝั่ง client กับผู้ใช้ทุกคน ไม่ได้ใช้ Firebase Auth จริง (ดูเหตุผล/ความเสี่ยงที่ยอมรับไว้ใน `firestore.rules`)
- Dark Mode ครอบคลุมเต็มรูปแบบเฉพาะฝั่ง Driver และหน้าตั้งค่าของอีก 2 role เท่านั้น (หน้าอื่นของ Ambulance/Agency ยังเป็นโหมดสว่างเสมอ)
- โมเดล AI สำหรับ Anti-Spoofing และ Accident Classifier เตรียมโค้ดไว้แล้วแต่ยังไม่มีไฟล์โมเดลที่เทรนจริงวางไว้ใน `assets/models/`
- ยังไม่มีระบบ retry อัตโนมัติเมื่อการซิงก์ข้อมูลไป Firestore ล้มเหลว (แอปจะแจ้งเตือนผู้ใช้ให้ลองใหม่แทน)

รายละเอียดการพัฒนาและการแก้ไขทั้งหมดตลอดโปรเจกต์ (เรียงตามลำดับ) ดูได้ที่ [`CHANGES_SUMMARY.md`](CHANGES_SUMMARY.md)
